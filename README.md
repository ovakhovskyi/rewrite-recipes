# rewrite-avro-trust

Maven-проект OpenRewrite-рецепта для миграции Spring Boot сервисов на Apache Avro 1.12.2.

## Сборка

Из директории проекта:

```bash
mvn clean install
```

Для сборки и запуска рецепта нужен JDK 25. Команда `mvn -version` показывает, какой JDK использует Maven. `mvn clean install` устанавливает JAR с координатами `org.arazei:openrewrite:1.0-SNAPSHOT` и байткодом Java 25.

## Запуск в сервисе

Из корня целевого Maven-проекта. Активируй Java-рецепт напрямую:

```bash
mvn org.openrewrite.maven:rewrite-maven-plugin:6.25.0:dryRunNoFork \
  -Drewrite.recipeArtifactCoordinates=org.arazei:openrewrite:1.0-SNAPSHOT \
  -Drewrite.activeRecipes=dev.myraif.rewrite.ConfigureAvroTrust \
  '-Drewrite.additionalPlainTextMasks=**/*.avsc' \
  -Drewrite.exportDatatables=true
```

Посмотри `target/rewrite/rewrite.patch`. Для применения замени `:dryRunNoFork` на `:runNoFork` и повтори команду. Если используешь корпоративный `settings.xml`, передай `-s /путь/к/settings.xml` при установке и запуске. Обе команды должны использовать один локальный Maven-репозиторий.

Маска в одинарных кавычках передаёт схемы `.avsc` текстовому парсеру. Если в конфигурации плагина уже переопределён `plainTextMasks`, включи в **этот** список обе маски — `**/*.avsc` и `**/META-INF/spring.factories`. Запускай на полном основном наборе исходников и ресурсов, включая существующий инициализатор и `spring.factories`. Если рецепт входит в миграцию с обновлением BOM, запускай его **после** обновления, когда на classpath уже разрешается Avro 1.12.2.

## Условия применения

- Каждый Maven-модуль проверяется отдельно. Нужен обычный JAR `org.apache.avro:avro:1.12.2` на compile и runtime classpath. Поддерживаются транзитивные зависимости и версии из dependency management. Другие версии, включая 1.11.5 и 1.12.1, пропускаются.
- В `src/main/java` должен быть ровно один верхнеуровневый класс с `@SpringBootApplication`. Его имя произвольно. Базовый пакет берётся из Java-декларации.
- Рецепт ищет определения record, enum и fixed в `.avsc` под `src/` каждого модуля, включая `src/avro`, `src/main/avro` и произвольные подкаталоги. Поиск также поддерживает производственный `sourceDirectory` из `avro-maven-plugin` и распознаёт Java-модели с `@AvroGenerated`. Доверенные пакеты берутся из подтверждённых namespace. Каталоги `src/test`, `src/it` и `src/testFixtures` исключены.
- Результат — `com.example.orders.config.AvroTrustInitializer` и его регистрация в `src/main/resources/META-INF/spring.factories`. Инициализатор дополняет действующий глобальный предикат Avro проверками точного совпадения пакетов.
- Существующие регистрации и комментарии сохраняются. Для ранее сгенерированного класса рецепт обновляет список пакетов и при необходимости восстанавливает регистрацию. Другая реализация в целевом классе, повторяющийся ключ инициализатора и неоднозначное приложение приводят к пропуску модуля. Сравнение с ожидаемым исходником учитывает различия CRLF/LF и обрамляющие пробелы. Другие пользовательские изменения трактуются как конфликт.
- Причины пропуска экспортируются в таблицу `ConfigureAvroTrust$Decisions` в каталоге отчётов плагина при `-Drewrite.exportDatatables=true`. Проект рецепта и целевой сервис используют отдельные POM. Рецепт не меняет зависимости сервиса.

## Проверка

`mvn clean verify` собирает JAR и запускает модульные тесты. Для проверки установленного JAR на реальном многомодульном проекте нужны Maven, JDK и Python 3:

```bash
mvn clean install
python3 src/it/verify.py
# На JDK 25 можно проверить сервис с целевым байткодом Java 25:
python3 src/it/verify.py --release 25
```

Скрипт создаёт отдельный временный Maven-проект и сравнивает содержимое всех исходных файлов до и после двух запусков рецепта. В одном сервисе Avro приходит транзитивно, модель генерирует avro-maven-plugin. Тест поднимает Spring Boot 4.1.2, проверяет обе регистрации и декодирует бинарное событие в сгенерированный класс с проверкой значения поля. Второй подходящий модуль имеет другой пакет приложения и модель с `@AvroGenerated`. Остальные модули проверяют пропуск старых версий, неподходящих scope, записи только в dependency management, схем только в тестовых каталогах, конфликта исходников и двух классов приложения. Дополнительный сценарий проверяет запуск напрямую с двумя namespace в разных каталогах под `src/`, пропуск тестовых схем и обновление существующего инициализатора.

## Явный выбор пакета

Основная команда автоматически определяет все пакеты. Если нужно выбрать один из обнаруженных пакетов, опция `trustedPackage` доступна через декларативный рецепт, как в `examples/myraif-bff-auth.yml`.
